### Цели

- **Показать превью амплитуды во времени и её распределения до детекции событий, сразу после открытия окна.**
- **Обновлять это превью при смене основного канала детекции.**
- **Использовать уже рассчитанную амплитуду (Trace_out после findSegmentMaxima) как источник и для временного ряда, и для распределения, то есть работать с амплитудой выборки, а не с амплитудами детектированных пиков.**

### Ключевые точки текущей реализации

- В autoEventDetectionGUI.m уже есть функция previewData(), которая:
  - собирает параметры в структуру params;
  - вызывает autoEventDetection(params) с params.detect = false;
  - передаёт результаты в plotRequest(...).
- В plotRequest(...):
  - Trace_out дополнительно агрегируется через findSegmentMaxima(Trace_out, numSegments);
  - строится временной ряд (Tile 1) и гистограмма (Tile 2) по этому агрегированному Trace_out;
  - нижние тайлы (3–4) используются только при реальной детекции с поиском вокруг стимулов.
- Сейчас previewData() фактически не вызывается (старый вызов закомментирован в changeDetectionType).

### План изменений

- **1. Автоматическое превью при открытии окна**
  - После загрузки и применения настроек в autoEventDetectionGUI (блок if ~isempty(settings)):
    - один раз вызвать previewData(), чтобы сразу показать:
      - на первом сабплоте — временной ряд сегментированного Trace_out;
      - на втором сабплоте — гистограмму распределения по этому же Trace_out с линиями outlier, 3*STD и текущим порогом.
- **2. Обновление превью при смене канала**
  - Найти место создания hMainChannel в autoEventDetectionGUI.m и расширить его Callback так, чтобы при смене канала:
    - вызывалась существующая логика changeDetectionType (если она нужна для UI);
    - затем вызывалась previewData() для пересчёта и перерисовки обоих сабплотов.
- **3. Использование амплитуды выборки для распределения**
  - В autoEventDetection:
    - всегда считать Trace_out по всему сигналу;
    - при UseTimeRange = true ограничивать по времени только данные для детекции, но не исходный Trace_out для превью.
  - В plotRequest:
    - всегда выполнять:
      - Trace_out = findSegmentMaxima(Trace_out, numSegments);
      - time_res = linspace(time_res(1), time_res(end), numSegments);
    - считать:
      - outlier = quantile(Trace_out, 0.999);
      - std3 = 3*nanstd(Trace_out);
    - строить гистограмму (Tile 2) по этому сегментированному Trace_out, то есть по амплитуде выборки, а не по амплитудам детектированных пиков;
    - сохранить текущие подписи и метрики (outlier, 3*STD, chosen_th).
- **4. Поведение после детекции (Check Detection)**
  - В checkDetectionCallback оставить вызов autoEventDetection(params) с params.detect = true.
  - В plotRequest:
    - Tile 1:
      - отрисовать временной ряд по сегментированному Trace_out;
      - поверх него отрисовать линии событий по events_detected (Lines(events_detected * timeUnitFactor, ...));
      - если включён UseTimeRange, xlim первого сабплота должны соответствовать выбранному диапазону, при этом findSegmentMaxima по-прежнему считается по всему сигналу.
    - Tile 2:
      - гистограмма распределения строится по тому же сегментированному Trace_out (амплитуда выборки);
      - метрики и подписи (outlier, 3*STD, chosen_th) общие и для превью, и для детекции.
- **5. Минимальные изменения UI и проверка**
  - Не добавлять новых кнопок:
    - автопревью при открытии окна;
    - автопревью при смене канала;
    - существующая кнопка Check Detection запускает детекцию и дорисовывает события.
  - После реализации вручную проверить:
    - что при открытии окна сразу видны оба сабплота для текущего канала;
    - что при смене основного канала превью обновляется;
    - что после Check Detection события видны на первом сабплоте, xlim уважают UseTimeRange, а распределение на втором сабплоте строится по амплитуде выборки.
